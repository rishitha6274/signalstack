# Audit evidence

Raw material from the three-stage audit of Signal Stack's own strategic reads, preserved verbatim so the numbers quoted in the top-level `README.md` can be checked rather than taken on trust. **Nothing here is edited, re-run or re-scored** — these are the files as they were produced, and the `scripts/` directory holds the harnesses that produced them, unmodified. `FINDINGS.md` is the written record of the first audit: the three defects it found (a retry notice that contradicted the validator, a withheld narrative that was not flagged as withheld, and an uncalibrated confidence field), the fix for each, and the baseline table of `3 / 2 / 1 / 7 / 6` failures across failure modes A–E. `before/` holds the ten raw strategic reads from the pre-fix 10-competitor run — the timeline, intent, prediction and recommendation for each competitor as the model actually returned them; these reads predate the `confidence` field entirely, which is why the current harness scores them differently (see the footnote in the top-level README). `after-pre-fix/` and `final/` hold the corresponding reads after the first round of fixes and after the final hardening pass respectively, both ten competitors plus a `_sweep.json` metadata file recording timing and rate-limit handling. The three `report_*.json` files are the harness verdicts: `report_before.json` is `before/` scored by the current `check.py` and gives `0 / 0 / 0 / 10 / 0`, `report_final.json` is `final/` scored by `audit_final.py` and gives `0 / 0 / 0 / 0 / 0`, and `report_after.json` gives `0 / 0 / 0 / 3 / 2` — an intermediate sweep over a directory named `after/` that was not preserved, so for that one only the summary survives and the raw reads are gone.

The scripts that produced each table are in `scripts/`, and their internal paths still point at `/tmp/audit/`, so they need repointing before they will run from a fresh clone. `check.py` is the standalone five-mode scorer (`A` overclaimed repetition, `B` ignored staleness, `C` prediction contradicts the latest trend, `D` missing calibration or verbatim grounding, `E` arithmetic or date error) and wrote `report_before.json`; `audit.py`, `audit_after.py` and `audit_final.py` are the per-sweep harnesses that read `before/`, `after/` and `final/` respectively, of which only `audit_final.py` uses the current field-based refusal test (`confidence == "none"`), and it produced `report_final.json` and the `3 / 2 / 1 / 7 / 6` → `0` figure quoted in the main README; `sweep.py` and `sweep_final.py` are the live sweep drivers that wrote the raw read directories, honouring `Retry-After` and spacing requests 10s apart; and `report_four.py` re-scores the four-read verification set. One honest caveat on reproducibility: **the original harness that produced the `3 / 2 / 1 / 7 / 6` baseline was revised during the project and no surviving copy of the original remains**, so the baseline cannot be re-derived from anything in this folder. The current scripts score `before/` at `0 / 0 / 0 / 10 / 0` instead, and the difference is mostly mode `D` — the `before/` reads have no `confidence` field at all, so all ten now fail the calibration check where the original scored seven. `check.py`, `audit.py` and `audit_final.py` also hardcode an absolute path to `data/seed_signals.json` under one contributor's home directory; that is a portability wart, not a secret, and it was left as-is so these files stay faithful evidence of what was run.
